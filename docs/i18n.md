# Le site en deux langues : comment c'est fait, comment on l'entretient

Depuis le 05.11.2026, le site existe en français (langue de base, à la racine) et en anglais
(sous `/en`). Une troisième langue (allemand, `/de`) suivrait le même mécanisme.

## Où vit le contenu

| Langue | Fichiers | Forme |
| --- | --- | --- |
| Français | `src/content/ia/{site,home,metiers,securite,ressources,ui}.ts` | `as const`, source des types |
| Anglais | `src/content/ia/en/{site,home,metiers,securite,ressources,ui}.ts` | mêmes exports, annotés avec les types de `shape.ts` |

- `src/content/ia/shape.ts` : le contrat. `Widen<typeof import("./home.ts")>` élargit les littéraux
  français (chaînes, tableaux) pour qu'une traduction ait la même forme sans les mêmes mots. Les
  modules déjà typés (`Metier`, `Resource`) gardent leur type. Une clé manquante ou en trop dans un
  fichier anglais est une erreur de typage, pas une page cassée.
- `src/content/ia/bundle.ts` : `CONTENT = { fr, en }` et `content(lang)`, qui déplie `ui`.
- `src/content/ia/lang.ts` : `langOf(pathname)` (tout ce qui commence par `/en` est anglais),
  `PAGE_PAIRS` (chemin français, chemin anglais de chaque page traduite), `alternate(path)` et
  `alternates(path)` (hreflang, sélecteur de langue, sitemap).
- `src/content/ia/ui.ts` et `en/ui.ts` : les textes d'interface (lien d'évitement, libellés,
  messages des formulaires, chemins des pages, `resourcePath`).

## Comment une page sait sa langue

`useContent()` (`src/components/ia/lang.tsx`) lit le chemin courant dans le routeur et renvoie le
contenu de la langue. Les composants ne lisent plus les modules français directement. Les liens
internes passent par `L` (un `Link` qui accepte un chemin en `string`, puisque la cible vient du
contenu). Hors composant (fonctions `head()` des routes, scripts), `content(lang)` fait la même chose.

Le `<html lang>` est posé dans `src/routes/__root.tsx` depuis le chemin. `pageMeta()` (`src/lib/seo.ts`)
déduit la langue du `path` qu'on lui donne et émet `og:locale`, `og:locale:alternate`, la canonique
et les `hreflang` réciproques : `fr-CH` et `en` quand la page existe dans les deux langues,
`x-default` toujours sur le français. Jamais de `hreflang` vers une page absente.

## Les routes

Une route par page et par langue, toutes minces :

| Français | Anglais | Corps partagé |
| --- | --- | --- |
| `index.tsx` | `en.index.tsx` | `HomePage`, `homeHead(lang)` dans `components/ia/pages.tsx` |
| `fiduciaires.tsx`, `administrations.tsx`, `pme.tsx` | `en.fiduciaries.tsx`, `en.public-administrations.tsx`, `en.smes.tsx` | `MetierPage`, `metierHead(metier)` |
| `securite.tsx` | `en.security.tsx` | `SecuritePage`, `securiteHead(lang)` |
| `ressources.index.tsx` | `en.resources.index.tsx` | `ResourcesPage`, `resourcesHead(lang)` |
| `ressources.$slug.tsx` | `en.resources.$slug.tsx` | `ResourcePage`, `resourceHead(lang, r)` |
| `mentions-legales.tsx` | `en.legal-notice.tsx` | texte dans la route |
| `politique-de-confidentialite.tsx` | `en.privacy-policy.tsx` | texte dans la route |

Les cinq anciens articles (`src/content/articles.ts`) n'existent qu'en français : ils n'ont pas de
`hreflang en` et la liste anglaise ne les montre pas.

## Les fichiers générés

| Commande | Produit |
| --- | --- |
| `npm run og` | `public/og/*.jpg` (français) et `public/og/en/*.jpg` (anglais) |
| `npm run dossier:pdf` | `public/dossier-securite-lx-studio.pdf` et `public/security-dossier-lx-studio.pdf` |
| `npm run sitemap` | `public/sitemap.xml`, avec les alternates `xhtml:link` et les dates (`updated` des articles, `PAGES_UPDATED` pour les pages fixes) |
| `npm run assets` | les trois à la suite |

À relancer après tout changement de titre, d'article ou de la page sécurité, dans l'une ou l'autre
langue, puis à committer. `public/llms.txt` est écrit à la main et porte une section « English ».

## Modifier un texte

1. Changer le français dans `src/content/ia/...`.
2. Changer l'anglais dans `src/content/ia/en/...` au même endroit. Le typage signale une clé
   oubliée ; il ne signale pas une phrase restée en français : relire.
3. `npm run typecheck`, puis `npm run assets` si un titre, un article ou la sécurité a changé, puis
   mettre à jour `PAGES_UPDATED` dans `scripts/sitemap.ts` (ou `updated` dans l'article).
4. `BASE_URL=<url> npm run verif:dashes -- --pages` : 0 tiret long dans les 29 pages.

## Les formulaires et les mails

Les messages de validation viennent de `ui.formErrors` de la langue de la page
(`diagnosticSchema(messages, sizes)`, `dossierSchema(messages)` dans `src/lib/forms.ts`). Le serveur
accepte les tailles d'équipe des deux langues. La notification interne reste en français et indique
la langue ; la copie envoyée au visiteur pour le dossier sécurité est dans sa langue, avec le PDF de
sa langue (`src/lib/contact.ts`).

## La démo

La vidéo reste en français dans les deux langues. La page anglaise le dit et affiche le texte
anglais complet sous la vidéo (`DEMO.chapters` de `en/home.ts`). Le `VideoObject` déclare
`inLanguage: "fr-CH"` sur les deux pages.

## Ajouter une langue

1. Copier `src/content/ia/en/` en `src/content/ia/de/`, traduire, garder les exports et les clés.
2. `lang.ts` : ajouter `"de"` à `Lang`, les paires dans `PAGE_PAIRS`, étendre `langOf`.
3. `bundle.ts` : importer les modules, étendre `CONTENT`. `shape.ts` ne change pas.
4. `seo.ts` : ajouter `de` dans `OG_LOCALE`, `HREFLANG`, `PLACE` ; `pageMeta` et `alternates` pour
   trois langues (une entrée hreflang par langue où la page existe).
5. Routes `de.*.tsx` sur le modèle des `en.*.tsx`, sélecteur de langue à trois entrées dans
   `Header.tsx` et `Footer.tsx`, scripts `og`, `dossier:pdf`, `sitemap`, listes de `verif/`.

## Poids

Les deux langues sont dans le bundle principal (166,8 ko gzip le 05.11.2026, contre 142,6 ko avant :
le contenu anglais pèse 24 ko). Pour ne charger qu'une langue, la suite logique est de sortir le
contenu du bundle principal : une route de mise en page par langue (`en.tsx` avec `<Outlet />`) qui
fournit le contenu par contexte, et des fonctions `head()` qui ne lisent que ce dont elles ont
besoin. Non fait dans cette première version.
